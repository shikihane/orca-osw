Source of truth for behavior: `docs/superpowers/specs/2026-11-14-osw-control-plane-design.md`.
This file fixes the module boundaries, names and data shapes so independent workers
can implement in parallel on one shared worktree. Do not edit this file from a slice.

Baseline: `pytest -q` = 682 passed before this change.

  helpers, stdlib only (sqlite3/json/uuid/datetime/pathlib/asyncio/anyio already used).
- Follow existing style: small functions, no abstraction layers without a caller.
- Tests: one file per slice under `tests/`, `tmp_path`, no live Orca, no network.

- The stale `skill/osw/__pycache__/mailbox.cpython-314.pyc` belongs to the superseded
  mailbox-steward draft. Ignore it; do not import or resurrect it.

## 4. Envelope (`mailbox/envelope.py`)

Canonical dict (exactly the spec §7 keys), validated by:

```python
KINDS = ("request","followup","answer","ask","report","blocked","status","stop",
         "ack","notice","timer","system")
FROM_ROLES = ("human","worker","watcher","system","router","timer")
TO_ROLES = ("router","worker","human","broadcast","dead")
REPORT_OUTCOMES = ("progress","waiting","ready","blocked","failed","dropped")
MAX_BODY_BYTES = 16 * 1024
MAX_CARD_BYTES = 1024

def new_id(prefix: str = "msg", *, now: datetime | None = None) -> str
    # <prefix>_YYYYMMDDTHHMMSSfffZ_<6 hex>  (UTC)
def default_priority(env: dict) -> int
def validate_envelope(raw: dict, *, now: datetime | None = None) -> dict
def trust_for(role: str) -> str
def card(envelope: dict, *, ticket: dict | None = None, summary: str = "") -> dict
def is_exact_command(text: str) -> bool
```

Validation rules:
- Fill `v=1`, `id`, `ts`, `state="queued"`, `attempts=0`, `lease=None`,
  `trace=""`, empty correlation keys, `thread_key=""`, `reply_to=""`,
  `dedupe_key=""`, `priority=default_priority(...)` only when absent.
- `from` must have a valid role; `from.trust` is forced to `trusted` for
  human/watcher/system/router/timer and `untrusted` for worker (a caller may
  request stricter, never looser). `to.role` must be a valid role.
- `kind` must be in `KINDS`; `report.body.outcome` must be in `REPORT_OUTCOMES`
  when present.
- JSON-encoded `body` (UTF-8, `ensure_ascii=False`) over 16 KiB raises
  `body_too_large`; wrong types raise `invalid_envelope`; `ttl_s < 0` or
  `priority` outside 0..3 raise `invalid_field`/`invalid_priority`.
- Priority floor: `from.role == "human"` -> 0; kind `ask`/`blocked` -> 1;
  kind `report` -> 2; everything else -> 3. `default_priority` returns that.
- `is_exact_command(text)`: one line, matches
  `^osw\s+(new|use|stop|status|list|logs)\b`, contains none of `;&|><`$`\n`
  and no backticks. Used by the fast path.

`card()` returns the §9.3 shape: `message_id`, `kind`, `from`
(`role:id`), `trust`, `intent`, `attention`, `priority`, `summary` (<=200 chars,
from `body.summary` else `body.text` else `body` first line), `tickets`
(`[{"id","stage"}]` when a ticket is supplied), `detail_hint`
(`osw mailbox show <id>`). Total serialized size <= 1024 bytes: truncate
`summary` until it fits, never drop the keys.

Semantics:
- `lease` eligibility: rows with `to_role` whose `state == "queued"`, or
  `state == "leased"` and `lease_until < now`. Group by correlation key
  (`ticket|agent|dispatch|ask|decision|thread_key`, first non-empty, else
  message id); only the oldest row per group is eligible (FIFO inside a
  correlation); eligible rows are ordered by `(priority, ts, id)`. Set
  `state="leased"`, `lease_owner=owner`, `lease_until=now+lease_s`,
  `attempts+=1` in one transaction. Returns leased rows.
- `ack` sets `state="acked"`, `settled_at=now`; already-acked with same owner
  returns True. `settle` sets `state="settled"`. `release` returns to
  `queued` (or `dead` when `dead=True`). `expire_leases` returns expired rows
  to `queued` and returns the count.
- `commit_decision` is one transaction: duplicate `decision_id` ->
  return False, no writes. Insert decision `state="committed"`; effects
  `state="pending"` (skip an existing `(kind,key)`); settle each id in
  `settlements`; insert outbox rows with `seq = max(seq)+1` per
  `(ticket_id, conversation)` in list order. Invalid input raises
  `decision_invalid`.
- `claim_effect` sets `state="running"`, `claim_owner`, `claim_until`;
  false if already running under a live claim. `finish_effect` with
  `state="done"` or `"dead"` or back to `"pending"` with the next `next_at`.
- `status()` returns the §18 JSON: `running` (lock pid alive), `pid`,
  `schema_version`, `queues` (queued+leased by `to_role`; missing roles 0),
  `oldest_age_s`, `leased`, `dead`, `spool_lag` (pending spool files count,
  computed by the caller-supplied `spool_lag_fn` or 0 — see note), `doorbell`
  (kv `doorbell:state` or "none"), `decisions_applied_5m` (count of decisions
  `applied` with `ts` within 300s). Note: `Store.status()` never touches the
  filesystem outside the DB; `mailbox_cli.status` fills `spool_lag` from
  `spool.pending_count(root)` and `running`/`pid` from the lock.

## 8. Fast path (`skill/osw/fastpath.py`)

Pure rules, one fixture per rule under `tests/fixtures/fastpath/<rule>.json`
(`{"rule": name, "cases": [{"name", "envelope", "context", "expect"}]}`).

```python
class Rule:
    name: str
    def apply(self, env: dict, ctx: dict) -> dict | None

RULES: list[Rule]
def evaluate(env: dict, ctx: dict | None = None) -> dict
def apply(store, env: dict, ctx: dict | None = None) -> dict
```

`evaluate` result:
```python
{"intent": str, "attention": "fyi"|"must_answer"|"human",
 "priority": int, "wake": "doorbell"|"",
 "decision": dict | None,      # human-command decision, author="human"
 "bookkeeping": list[dict],    # [{"op":"attach"|"stage"|"settle"|"expire"|"outbox", ...}]
 "reason": str}
```
`ctx` keys: `now` (ISO), `tickets` (list from the store), `doorbell` (str),
`queued_router` (int).
Rules (each pure, first match wins, all fixture-covered):
1. `expire_ttl` — `ttl_s>0` and older -> bookkeeping expire, attention fyi.
2. `human_command` — trusted human `request` with `body.command` passing
   `is_exact_command` -> Decision mapping: `new`->`accept`, `use`->`followup`,
   `stop`->`stop`, `status`/`list`/`logs`->`noop` (payload `{"command": ...}`),
   reason "human command", confidence 1.0, author "human".
3. `human_request` — human request -> intent request, attention must_answer,
   priority 0.
4. `ask` — kind ask (worker/watcher) -> intent answer, attention must_answer,
   attach/stage `waiting_answer` when a ticket matches.
5. `blocked` — kind blocked -> intent resolve, attention must_answer.
6. `report_result` — report outcome ready/failed/dropped -> intent
   accept_result, attention must_answer, stage review (or stopped for dropped).
7. `report_progress` — report outcome progress/waiting -> attention fyi,
   bookkeeping settle (progress only), stage working.
8. `status_request` — kind status to router -> intent answer_status, fyi,
   bookkeeping outbox notice with `{"line": "# [osw] status ..."}` counts.
9. `notice` — kind notice/ack/timer/system -> attention fyi, no wake.
10. `wake` — queued router cards and `ctx["doorbell"] != "pending"` ->
    `wake="doorbell"`.
Attach matches `correlation.ticket` then `thread_key`.
`apply(store, env, ctx)` performs `bookkeeping` through the store
(attach/update stage, settle, add_effect for outbox) and commits `decision`
when present. It never launches, replies, or chooses providers.

## 10. Dispatcher (`skill/osw/dispatcher.py`)

```python
ACTIONS = ("accept","followup","answer","stop","retry","reject","escalate","noop","close")
ANSWER_TEMPLATE = "# [osw] answer {decision_id}: {text}"
MAX_ANSWER_BYTES = 4096

def validate_decision(d: dict) -> dict
def plan_effects(decision: dict) -> list[dict]
    # [{"kind","key","payload"}] per action; keys exactly as the spec §12 table
def commit(store, decision: dict, *, message_id: str = "") -> bool
    # validate, load mandate for the ticket (create on accept when missing),
    # close/expiry checks, then store.commit_decision(decision, effects=...,
    # settlements=[message_id] when given, outbox for escalate)
class Hooks(Protocol):
    async def launch(self, ticket: dict, payload: dict) -> dict   # -> {"agent_id","terminal","dispatch_id"}
    async def followup(self, ticket: dict, payload: dict) -> None
    async def answer(self, ticket: dict, payload: dict) -> None   # payload has ask/text/template
    async def stop(self, ticket: dict) -> None
async def run_pending(store, hooks, *, now: float | None = None,
                      owner: str = "", limit: int = 20) -> list[dict]
async def apply_effect(store, effect: dict, hooks, *, owner: str = "") -> dict
```

Rules: `answer` rechecks `store.is_ask_open(ticket, ask_id)` before calling the
hook (else `ask_not_open`, effect done with a recorded result); `accept` refuses
a ticket already `stopped`, and reuses the existing assignment; `retry` requires
`attempt < mandate.max_retries`; `close` requires no open asks and no running
assignment (`close_precondition_failed` otherwise); every hook exception leaves
the effect `pending` with backoff `min(60, 2**attempts)` seconds (delivery retry
sequence 2 s doubling to 60 s); after `max_attempts = 8` the effect becomes
`dead` and a human notice outbox row is enqueued (`mandate_denied` included).
Every applied decision emits `router_applied` through `log.emit_event` when a
`root` is supplied via `store.root` (Store may carry an optional `root: Path|None`
attribute set by callers for events; events never affect behavior).

## 11. Adapters (`mailbox/adapters.py`)

Independently disableable, config at `mailbox_dir/adapters.json` (optional):
`{"enabled": {"log_file": true, ...}, "log_file": {"paths": [...]},
"crash_file": {"paths": [...]}, "build_result": {"paths": [...]},
"process_exit": {"pids": []}}`. State per adapter in `mailbox_dir/adapters/<name>.json`.
`run_once(root, *, now=None) -> dict[str, dict]` polls enabled adapters and
writes at most one digest envelope per adapter per burst via
`spool.write_envelope`, `thread_key` = file path / build id / pid, role
`system`, kind `system`, body `{"event": "...", "summary": ..., "count": n,
"path": ...}`. A failing adapter emits one `system` event
(`adapter_failed`) through `log.emit_event` and disables itself in its state
file; others keep running. Rotation/truncation (size shrink or inode/ctime
change) restarts the read position. Adapters never touch the store.

## 12. Daemon and delivery (`mailbox/daemon.py`, `mailbox/delivery.py`)

```python
# delivery.py
async def deliver_outbox(store, notify, *, limit: int = 50,
                         now: float | None = None) -> list[dict]
    # ordered per (ticket_id, conversation); notify(conversation, line) -> None;
    # success -> receipt "sent"; failure -> retry/backoff then dead
def conversation_address(target: dict) -> str   # {"terminal": "term_x"} -> "terminal:term_x"; {"session": ...} -> "session:<id>"

# daemon.py
def acquire_lock(root: Path) -> dict        # {"pid", "started_at"}; dead pid reclaimed; live foreign -> mailbox_locked
def release_lock(root: Path) -> None
def is_running(root: Path) -> tuple[bool, int]
def read_status(root: Path) -> dict | None
async def run(root: Path, *, once: bool = False, poll_s: float = 1.0) -> None
class CLIHooks:   # production hooks; async methods shell out to the OSW CLI
    def __init__(self, root: Path) -> None
def router_notify(store, root: Path, *, now: float | None = None) -> None
    # doorbell: one pending, suppress second, ring again after lease/120s,
    # then a human attention notice. Line exactly:
    # '# [osw] mail pending=<n> run="osw mailbox wait --as router --timeout 0"'
```
`run` tick: ingest spool -> fastpath each new message (via `spool.ingest`
returning rows, then `fastpath.apply`) -> `dispatcher.run_pending` ->
`delivery.deliver_outbox` -> expire leases -> doorbell -> write `status.json`
-> stop when `stop_path` exists. Exceptions per unit are logged as events and
never kill the loop. Lock reclaim only when the recorded pid is not alive.

`CLIHooks` runs `[sys.executable, <root>/skill/osw.py, "new"|"use"|"stop", ...]`
with `cwd=root`, parses `Created <agent_id> on terminal <handle>` from `new`,
and answers via `orca_cli.run_orca("orchestration","reply","--id",ask,"--body",text)`.
Pass `--caller-terminal <handle>` taken from the ticket origin transport
(`terminal:<handle>`) when present, else `--no-notify`. These hooks are the only
place that builds those argv lists.

## 13. Mailbox CLI (`skill/osw/mailbox_cli.py` + `cli.py`)

Verbs and JSON shapes:
- `start [--json]` -> spawns `[sys.executable, <osw.py>, "mailbox", "serve"]`
  detached with `cwd=root`, waits for the lock (<=10 s), prints
  `{"running": true, "pid": n}`; already running is a success.
- `stop [--json]` -> writes `daemon.stop`, waits <=10 s; `{"stopped": true}`.
- `serve` (hidden) -> `anyio.run(daemon.run, root)`.
- `status [--json]` -> §18 JSON, with `spool_lag` from
  `spool.pending_count` and `running`/`pid` from the lock.
- `send --kind K --body-json J|--text T [--from-role R] [--from-id I]
  [--to-role R] [--ticket T] [--agent A] [--thread-key K] [--dedupe-key D]
  [--priority N] [--reply-to M] [--json]` -> writes the envelope to the spool
  (default roles human -> router), prints `{"id": ...}`.
- `wait [--as router|human] [--timeout SECS] [--max N] [--json]` -> lease and
  ack cards for the role; register the router binding and consume the doorbell
  when `--as router`; returns `[card, ...]` (JSON) or one line per card.

- `trace <message-id|ticket-id> [--json]` -> `{"message", "ticket",

## 14. Watcher sink (`watcher.py`)

Add one best-effort sink, never allowed to break the turn:

```python
from osw.mailbox.spool import write_envelope
self._spool(kind="report", outcome=..., body={...}, dedupe_key=...)
```
- report on turn end with `outcome` from the completion source (`ready` for a
  verified handoff/completed turn, `failed` for error, `dropped` for lost or
  interrupted), `body` = handoff path/summary/completion_source/tools_observed,
  `thread_key` = record `ticket_id` or agent id, `correlation.agent` = id.
- ask when relaying a supervised worker question: kind `ask`, `correlation.ask`
  = Orca message id, `dedupe_key` = the same id, priority 1, `body.text`.
- blocked when reporting a blocker: kind `blocked`, body `{"kind","screen"}`.
- `report_key`: one stable key per turn, generated at turn start and stored in
  the agent record (`_update(report_key=...)`), reused after a watcher restart.
- All sink calls wrapped in `try/except Exception`, emitting `spool_sink_failed`
  at WARNING. Existing notification behavior is unchanged.

## Addendum A — independent review fixes (2026-11-14)

These bindings are added or confirmed after the independent review. Worker slices
below must implement them; the original sections keep their semantics.

1. `Store.ticket_for_agent(agent_id: str) -> dict | None`: newest ticket (by
   `updated_at`) whose `assignments` contains that `agent_id` and whose stage is
   not `done`/`stopped`; `None` otherwise.
2. `Store.effect_exists(kind: str, key: str) -> bool`.
3. `Store.pending_effects(now, limit)` returns due `pending` rows **and**
   `running` rows whose `claim_until < now` (expired claim reclaim), ordered by
   `next_at, id`; `claim_effect` accepts an expired-running row.
4. `dispatcher.commit` must:
   - for `accept` with no ticket, run the base-mandate and `open_from` checks
     **before** `create_ticket`, then re-check with the stored mandate; never
     leave an orphan ticket when the decision is refused;
   - after commit, if a planned Effect was skipped because `(kind,key)` already
     exists, mark the Decision `failed` with result `duplicate_effect` and
     enqueue one human attention notice — two distinct `decision_id`s must never
     disappear silently;
   - `answer` calls `store.close_ask` after a successful reply; a second answer
     for the same ask is recorded and applied with result `ask_already_answered`
     and no retry;
   - `close` requires no `running` assignment and no open ask; the fast path
     finalizes assignments from reports (`done` for ready/failed, `stopped` for
     dropped) and `stop` finalizes to `stopped`;
   - enforce `mandate.check_open_from` when a Ticket would be created:
     `origin["role"] == "human"` counts as the empty human source (allowed);
     every other source must be listed;
   - `decision_id` matches `^dec_[A-Za-z0-9_.:-]{1,120}$` (no whitespace or
     control characters); answer `text` has CR/LF and other control characters
     replaced by single spaces before the cap and single-line checks.
5. `fastpath` attach: when `correlation.ticket` and `thread_key` match no ticket,
   resolve `correlation.agent` through `Store.ticket_for_agent`; the resolved
   ticket carries the stage/report/open_ask ops. A `report` with outcome
   ready/failed sets the assignment `done`; dropped sets it `stopped`.
6. `fastpath` human command: commit through
   `dispatcher.commit(store, decision, message_id=env["id"])` (lazy import), so
   Effects are planned and the Dispatcher executes them. A `status` request
   produces the bookkeeping op `{"op":"outbox","conversation":...,"payload":
   {"line":...}}` written with `store.outbox_put` — never an Effect.
7. `daemon.CLIHooks` subprocess env removes `OSW_ROLE`, `OSW_ROLE_TOKEN` and
   `ORCA_TERMINAL_HANDLE`: a Router shell never makes its own `new`/`use`/`stop`
   refuse, and the daemon inherits no role.
8. `daemon.router_notify` addresses attention to the ticket origin conversation
   when that is a real `terminal:`/`session:` address. A headless
   `local:<pid>` router binding is not a delivery target: log `doorbell_skipped`
   once per interval and never dead-letter the doorbell.
9. `daemon.tick` calls `mailbox.adapters.run_once(root)` inside its own guard;
   adapters stay optional (no config or no enabled adapter -> no work).
10. `mailbox send` and `mailbox decide --author human` are refused with
    `router_forbidden` when `identity.current_role(root) == "router"`;
    `decide --author router` requires the router identity. The default author
    follows the current role. A human in the same terminal keeps the human
    identity.
11. Tests must exercise the watcher-produced shape (`correlation.agent`, no
    `ticket`) and must close a Ticket without hand-editing assignment state.
